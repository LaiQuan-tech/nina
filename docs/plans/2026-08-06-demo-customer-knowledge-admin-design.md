# Demo 客戶知識後台設計

## 背景

`Nina-pitch` 將系統的第二個經營目標定義為「減輕交接與培訓時間」，並列出會員身份整合、客戶樣貌與偏好記憶、對話與需求、報價／稿件／工單知識庫、歷史案件、服務摘要及回訪提醒七項能力。

目前 Nina 已具備會員、收稿對話、稿件、工單與基本後台，但資料仍分散在案件與工單畫面，尚未形成能展示完整客戶脈絡的後台。這次先建立可操作的 Demo 雛形，以全虛構資料展示未來正式 CRM 的使用方式。

## 目標

- 將簡報的七項能力全部映射到可操作的後台畫面。
- 以客戶為核心整合樣貌、偏好、對話、報價、稿件、工單與回訪。
- 使用 Supabase 持久化 Demo 資料，讓搜尋、編輯與完成回訪可以保存。
- Demo 資料與正式資料明確隔離，可安全、重複建立與清除。
- 不在雛形階段實作真正的 AI 摘要生成、外部通知或 ERP 寫入。

## 方案選擇

採用「客戶中心式 CRM」。相較於把七項能力拆成七頁，客戶中心能讓 Demo 從總覽、客戶列表一路進入單一客戶完整歷程，更貼近員工交接情境；相較於單頁儀表板，也能提供足夠的互動深度。

## 後台資訊架構

側邊選單調整為：

1. 營運總覽
2. 客戶知識庫
3. 服務知識庫
4. 追蹤與回訪
5. 收稿案件
6. 網站圖片
7. 管理員帳號

### 營運總覽

總覽呈現：

- 客戶總數
- 本月新客戶
- 進行中報價
- 本月收稿量
- 待回訪數
- 逾期提醒數
- 最近 30 天互動趨勢
- 客戶產業分布
- 熱門材質／服務排行
- 今日待辦與最近活動

圖表使用 CSS 或 SVG，避免為雛形引入大型圖表依賴。

### 客戶知識庫

列表支援公司、聯絡人與手機搜尋，並可依客戶等級、產業、狀態和標籤篩選。每列顯示最近互動、累積案件、累積報價與待辦數量，Demo 客戶使用明確標記。

客戶詳情分成：

- 客戶樣貌：公司、產業、付款習慣、等級、聯絡偏好及標籤。
- AI 服務摘要：客戶特性、價格敏感度、溝通方式及服務注意事項。
- 偏好記憶：常用材質、尺寸、加工、交貨方式與常購產品。
- 完整歷程：對話、需求、報價、稿件、工單及回訪的時間軸。

AI 摘要、偏好與服務注意事項可由管理員編輯保存。Demo 階段使用預先建立的摘要，不呼叫 AI 重新生成。

### 服務知識庫

提供跨客戶搜尋，資料來源包含報價、稿件／工單與對話內容。搜尋結果可依類型、客戶、日期及狀態篩選，並連回客戶詳情、案件或既有工單頁。

### 追蹤與回訪

以「已逾期、今天、接下來七天」三組呈現提醒。每筆包含客戶、原因、優先度、指派人員、預定日期與最近服務摘要，支援新增、完成與延期。

## 七項簡報能力對應

| 簡報能力 | 後台落點 |
| --- | --- |
| 會員系統與客戶身份整合 | 客戶知識庫的身份與聯絡資料 |
| AI 客戶樣貌與偏好記憶 | 客戶樣貌、偏好及摘要卡 |
| 客戶對話與需求紀錄 | 客戶詳情時間軸與服務知識搜尋 |
| 報價、稿件與工單知識庫 | 服務知識庫與客戶歷程 |
| 歷史案件快速查詢 | 客戶列表搜尋、篩選及詳情連結 |
| 客戶服務重點自動摘要 | 可編輯的預生成 AI 服務摘要 |
| 智慧客戶追蹤與回訪提醒 | 追蹤與回訪工作區 |

## Demo 資料

建立約十位完全虛構的台灣客戶，涵蓋月結熟客、高價值、新客、價格敏感、沉睡、待報價與待回訪等情境。

資料量：

- 10 位客戶
- 20–25 段對話／需求紀錄
- 15–20 筆報價
- 30–40 筆稿件與工單
- 12–15 筆回訪提醒

使用固定 UUID 與 `upsert`，seed 可重複執行。清除模式只刪除 `is_demo=true`，並按相依順序移除提醒、報價、工單、案件、客戶樣貌及會員。電話使用明顯的測試號碼，Email 使用 `example.com`，公司與人物均為虛構。

## 資料層與 API

後台 Server Components 透過單一客戶知識資料層讀取聚合資料：

- 儀表板統計與趨勢
- 客戶列表及篩選
- 客戶完整詳情與統一時間軸
- 服務知識搜尋
- 回訪分組

可寫入 API：

- 更新客戶樣貌、偏好、摘要與服務注意事項
- 新增回訪提醒
- 完成或延期回訪

所有寫入 API 必須重新驗證管理員 session、檢查同源請求、使用欄位白名單並驗證字串長度、日期、列舉值及 member ID。Demo 雛形不提供刪除正式客戶或修改歷史對話／工單的功能。

## UI 原則

- 延續現有後台清爽白底、灰藍資訊層級，不複製簡報的展示版式。
- 重要統計用數字卡，次要資訊用標籤與小型趨勢圖。
- 客戶詳情在桌機使用雙欄摘要加時間軸，手機改單欄。
- Demo 標記在列表、詳情與總覽都清楚可見。
- 搜尋、篩選及回訪操作都有空狀態、載入狀態與錯誤訊息。
- 不以顏色作為唯一狀態提示。

## 安全與隔離

- 所有頁面維持後台 middleware 與頁面端管理員驗證。
- Demo 資料不會觸發 Email、LINE、外部 ERP 或其他通知。
- 前台會員登入、快速入會與紀錄頁排除 `is_demo=true`。
- `submitted=1` 等前台查詢參數只控制顯示，不能作為權限或資料依據。
- 清除 Demo 資料的腳本必須先確認目標資料皆有 `is_demo=true`，不提供廣泛刪除指令。

## 驗收標準

- 簡報右側七項能力都有明確、可操作的後台落點。
- Demo 資料可重複建立，不產生重複列。
- 客戶列表可搜尋與篩選，並能進入完整詳情。
- 客戶詳情同時顯示樣貌、偏好、AI 摘要及跨來源歷程。
- 摘要與偏好可編輯保存。
- 服務知識庫可跨報價、稿件／工單和對話搜尋。
- 回訪提醒可新增、完成及延期，重新整理後狀態仍保留。
- 前台無法看見或登入 Demo 客戶。
- 未登入管理員無法讀取或寫入後台資料。
- production build、單元測試、桌機及手機瀏覽器驗收通過。
